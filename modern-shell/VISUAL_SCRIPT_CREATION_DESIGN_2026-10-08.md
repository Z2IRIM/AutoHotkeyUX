## 意图与范围

用户要求先将脚本创建流程改为可视化，完成后再做 AHK 转译。本阶段将“转译”按前文理解为 **已有 AHK → 可视化流程**，留到后续阶段；本阶段需要 **可视化流程 → AHK v2** 的受支持动作生成，才能形成真正可运行的创建流程。

沿用当前 WinUI 3 应用、绿色 H 图标、窗口比例、运行/停止/重启和登录启动服务。采用动作卡片；用户不必编写 AHK 代码即可创建受支持流程。预览保留现有英文产品界面。主项目基线为 `e871fb1a328834a7d6b2b395321c764da4293e61`，原有 `RelayPrompt.md` 不属于本阶段。

## 一个完整 Gate

1. New Script 进入动作卡片编辑器：名称、位置、触发器、窗口条件、动作库、流程和参数。
2. 支持快捷键与“脚本启动时”两类触发；条件为任意窗口或指定应用活动窗口。快捷键通过修饰键与键选择器配置。
3. 六类顺序动作：打开程序/文件、打开文件夹（文档/桌面/自定义）、打开 HTTP(S) 网页、发送文字、发送受支持按键组合、等待。
4. 添加、选择、删除、拖拽或按钮排序，撤销/重做；窄窗口重排参数区域。代码预览默认折叠。
5. 校验后保存结构化流程和生成的 `.ahk`，进入现有 Scripts 管理；创建不隐式运行真实动作。
6. 本阶段自己创建的流程可重新进入可视化编辑器。既有纯代码脚本仍使用当前编辑器入口，源代码反向转译不进入本 Gate。

本阶段不包含任意分支/循环、录制器、图像识别、自由代码块或通用 AHK 解析器。窗口条件属于本阶段的条件支持，作用于整条流程，不能冒充完整 if/else 图形编程。

## 界面与编辑语义

- 复用 New Script 路由和主界面样式；左侧动作库、中间有序卡片、右侧当前选中步骤参数。窄窗口将参数移到流程下方。
- Trigger 是不可删除、不可排序的流程入口。启动触发时隐藏快捷键字段；应用条件启用时显示可执行文件名。
- 参数变更只更新草稿；选择卡片、重新排序及导航不应丢失草稿。UI 不执行动作，也不将预览当作实际运行。
- Create script 明确创建文件；成功后留在应用内，提供打开 Scripts 和编辑已创建流程的入口。运行使用现有显式 Run。
- 保存既有可视化流程后，运行中的解释器仍需 Restart 才使用新代码，沿用现有语义。

## 持久化和代码边界

- 使用有版本的强类型流程文档，建议同名 `<name>.ahk.flow.json`，保存触发器、动作 ID/类型/参数、文档 revision 和生成代码 SHA-256。动作按文档顺序执行。
- 流程文档是可视化编辑依据；AHK 生成器是单一纯转换入口，校验后产生稳定 UTF-8 v2 代码。文本、引号、反引号和换行按 AHK 规则转义；路径不得当作任意代码插入。
- 复用现有目录、命名和非覆盖语义，分配名字时同时检查 `.ahk` 与伴随流程文件。既有 `CreateScript` 的无覆盖意图需由新保存服务在文件句柄边界加强，不引入另一套目录扫描/进程管理。
- 两个文件无法作为一个普通文件原子提交：保存服务需要暂存、独占检查、失败回滚和恢复标记。不得将“写了两个文件”描述为完整原子事务。部分保存或文件缺失时显示具体状态，不能自动覆盖唯一有效副本。
- 编辑前核对 AHK 内容哈希和文档版本。发现手工修改、缺失流程数据或未知版本时保留文件并报告原因；禁止静默重生成。用户确认转换/导入的产品流程属于后续阶段。
- JSON 或未知参数不作为可执行代码。版本、动作数、文本大小、路径长度、等待范围、快捷键和动作类型严格校验。预览的局部校验不代替正式保存服务校验。

## 模块和复用

- `VisualScriptDocument`：强类型版本化流程、触发器与动作定义。
- `VisualScriptValidator` / `VisualScriptGenerator`：一致的边界校验和确定性 AHK v2 输出，不依赖 UI。
- `VisualScriptStore`：草稿/伴随文档、双文件保存恢复、外部修改检查，复用现有脚本目录和命名边界。
- New Script 视图及按职责分开的编辑 partial/view-model：选择、排序、参数和撤销状态；复用 MainWindow 页面路由与既有 WinUI 控件。
- Scripts 编辑路由按有效伴随文档选择可视化编辑，其他脚本继续复用 `AutoHotkeyIntegration.EditScript`；执行仍由 `ScriptExecutionService` 与 `ScriptStartupService` 管理。

不引入 Blockly/WebView2 编辑器依赖。本 Gate 的动作卡片和参数可以由原生 WinUI 实现。已有离线文档浏览器的安全设置保持原有职责。
