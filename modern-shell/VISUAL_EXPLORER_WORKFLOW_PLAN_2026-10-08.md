# 可视化终端与解压工作流：阶段规划

日期：2026-10-08。核对基线：`763fe2af65c63d68b2ce2fe1ae17afab0bd9e39b`。状态：用户已确认阶段规划；可配置动作交互预览已提供，等待 UI 反馈后进入产品实现。本次未修改产品代码、启动原生应用测试或切换现有脚本。

## 阶段目标

用户仅通过可视化脚本编辑器，能够从空白流程创建、配置、保存、重开和运行以下行为：在文件资源管理器及桌面按 Alt＋左键，点击文件夹或文件区空白时打开该目录的终端，终端从触发点上方出现；点击支持的压缩文件时解压到配置的目录。全程无需编辑生成的 AHK。

建议作为一个完整 Gate「可视化复刻 Explorer 快捷工具」交付，以下条目是同一 Gate 的内部执行清单。动作数量不是验收指标；参数完整、数据可连接、结果确定及真正可运行才是。

## 当前能力与实际缺口

| 方面 | 已有能力 | 本阶段需要完善 |
|---|---|---|
| 入口 | 可选键盘／鼠标快捷键、修饰键，作用域包含 Explorer 和桌面 | 鼠标触发配置表达点击、文件区背景和无效目标的处理；拖拽保持原有排除规则 |
| 上下文 | 点击对象、单个选中对象、当前目录；已有 Path／Directory／Name／Extension 输出 | 清楚显示目标种类、触发坐标、父目录及名称语义；无有效对象时允许静默结束 |
| 分支 | If／Else 已能判断文件夹、文件、压缩包、扩展名及空值 | 改善分支添加和数据来源展示，避免用户为简单类型分流反复嵌套或选错字段 |
| 终端 | OpenTerminal 接收目录，并复用终端启动和鼠标上方定位 | 程序、位置、尺寸、间距仍依赖全局设置；节点没有独立配置及可供后续动作使用的就绪结果 |
| 解压 | 接收归档路径、可选目标根目录；输出新目录，支持 ZIP／7z／RAR／TAR／TAR.GZ／TGZ 后缀 | 命名和重名策略不能选；显式流程当前每次启动短命 EXE 并同步等待，缺少完整的步骤状态和失败定位 |
| 动作库 | 16 个固定动作，分类为原生浮动菜单 | 支持收藏节点配置，形成用户自己的动作预设；补充必要的通用路径和流程动作 |
| 运行管理 | 有创建、运行、启动选择、冲突检测及停止能力 | 让用户理解与原内置 Alt＋左键的冲突，提供明确的改键或替换入口及失败恢复 |

源码依据：`VisualFlowExamples.Explorer()` 已使用点击对象、文件夹判断、压缩包判断、终端和解压动作组成同一快捷键流程。因此，基础逻辑已具备，完善的重点是可配置程度、编辑可理解性及与现有工具的行为等价性。

## 路线选择

可采用「两个场景向导」或「可配置动作＋结果引用＋预设」两种路线。场景向导能快速填完两张表，但其他组合需要继续增加专用界面。推荐第二种：完善现有通用编辑器，提供三份可编辑示例作为入口。这样终端／解压配置既能单独使用，也能接到其他动作之后。

### 推荐工作流

1. Alt＋左键，仅作用于 Explorer 和桌面。
2. 获取本次点击上下文，保留触发时坐标及目标路径。
3. 目标为文件夹或文件区背景：将目标目录传给 OpenTerminal。
4. 目标为支持的压缩文件：将目标路径传给 ExtractArchive。
5. 普通文件、工具栏、不可解析的虚拟对象：按默认规则静默结束。

同一组合的两个独立脚本不能在相同作用域内同时运行。默认推荐一个流程的两个分支；单独示例仍可创建，并为它们选择互不冲突的快捷键。

## 动作与参数范围

### 完善现有节点

- **点击对象／当前目录**：显示路径、目标类别、可打开目录、父目录、文件名及扩展名；触发位置以明确的上下文来源提供。文件夹自身和父目录使用不同标签。获取不到有效目标时，默认停止本次流程且只记录原因。
- **OpenTerminal**：目录可选固定路径或前序结果；配置方式可选继承应用设置或独立配置。本阶段程序保持现有 Auto／Windows Terminal／Windows PowerShell；节点可设置位置（上、下、左、右、屏幕居中）、宽高和距触发点的间距。默认仍为上方、800×440 DIP、间距12 DIP；按目标屏幕的 DPI 和工作区裁剪。
- **终端就绪**：提供有界的等待选项、成功状态及真正属于此次启动的 WindowId，支持接到「激活窗口」等已有动作。只有取得就绪结果后才可引用窗口；超时显示失败，不匹配或移动原有终端窗口。
- **ExtractArchive**：归档来源可选点击对象、前序结果或固定文件。目标根目录可选旁边、固定目录、前序目录结果或继承应用设置；输出子文件夹名称可选原归档名或由文字／前序字段组合。重名策略为自动编号或报错，默认自动编号。
- **解压结果及错误**：成功后输出实际新目录，可以接「打开文件夹」或「通知」。操作失败停止当前流程，可配置显示提示或仅记日志；不把未完成的目录当作成功结果。
- **If／Else**：保留已有类型判断，增加与新增路径结果匹配的存在性判断；数据来源使用可读的字段标签，输入类型不匹配时就地提示。可通过现有分支实现上面的终端／解压分流。

### 补充五个通用动作

| 动作 | 可配置内容 | 服务于本阶段的用途 |
|---|---|---|
| 读取路径属性 | 输入路径；输出存在性、种类、父目录、名称、无扩展名名称等 | 固定路径或前序路径也可用于条件判断及命名 |
| 拼接路径 | 基础目录＋文字或前序字段组成的路径段 | 可视化形成解压目录，免写字符串表达式 |
| 创建目录 | 固定或前序路径；已存在的目录可复用，若同名文件存在则失败 | 为动态解压根目录补齐准备步骤，输出实际可用目录 |
| 停止本次流程 | 原因及是否提示 | 普通文件／无效对象分支明确结束 |
| 通知 | 标题、消息，可插入前序字段 | 显示实际终端／解压结果 |

组合字段使用类型明确的结果引用和文字片段，不接受需要用户编写的 AHK 表达式。结果只在当前执行及合法分支内可见，保留现有缺失引用和跨分支保护。

### 用户动作预设

配置好的单个动作可以命名并存到「我的动作」，例如“上方打开 1000×600 终端”“解压到工作目录”。预设保存节点参数，插入时创建新的动作身份；不保存其他流程的步骤 GUID，动态输入在当前流程重新绑定。用户可管理自己的预设，内置动作仍由程序维护。多动作封装、批量循环等作为后续独立阶段。

## 编辑体验

- 保留已经交付的右侧浮动动作分类、紧凑流程行和加高编辑区。
- 右侧属性按「输入」「操作设置」「结果」「高级」组织，属性区内部滚动，新增字段不撑高整排三栏。
- 路径和文件提供浏览入口；前序结果显示“步骤名 → 字段”，同时提示字段类型。节点可改显示名称、复制和保存为预设。
- 动作摘要显示实际配置，例如“点击目录 → Windows Terminal · 上方 · 1000×600”；结果不靠用户理解参数名猜测。
- 提供终端、解压、智能分流三份可编辑示例。验收仍从空白搭建，避免只证明预置示例可运行。
- 执行后在应用内显示分支、动作结果、输出目录及失败步骤。日志记录请求身份、耗时和失败原因，保持现有有界记录方式。

## 工程与兼容性决定

1. **先保护旧生成版本。** `VisualFlowStore.Open()` 不仅检查哈希，还按现行生成器逐字节重算源文件。直接改 v2 的共享辅助资源会让既有流程被判为手改。本阶段应固化 v1/v2 的生成契约和 v2 资源快照，以新格式承载新节点参数；旧流程继续读取，不批量改写。使用新能力并保存时才升级。
2. **参数按节点类型归属。** 终端设置、解压设置、文字／结果组合分别使用明确的模型和校验，避免继续把无关字段堆进一张通用参数表。复用原结果引用、编辑历史和文件成对存储，不新建平行编辑器。
3. **复用终端底层。** 复用窗口归属识别、DPI／工作区裁剪和短时定位队列；新节点提供每次启动的参数快照及就绪返回能力。继承全局时仅继承操作参数，不被原内置快捷键的启停开关约束。
4. **复用解压服务及既有队列。** 扩展已有管理器调度，为显式流程请求增加参数快照、请求身份、完成结果和状态查询；暖管理器处理正常请求，冷路径仍复用同一解压服务。保留旧命令及原内置工具语义。已接收请求不会因等待超时再启动一次解压，重复请求按身份去重。
5. **捕获先于排队。** 保存本次点击目标和坐标后，把耗时操作交给有界调度；不让长期解压阻塞鼠标入口。状态和结果按每次执行隔离，快速连续点击不能拿到另一轮的结果。
6. **继续保护文件。** 解压保留现有目录穿越、符号链接、CRC、输出预算、暂存提交及不覆盖保护。密码包、分卷包不纳入此 Gate 的新增支持，明确报告其未支持情况。
7. **冲突切换可恢复。** 可以先保存流程；启用时检查原内置工具及已运行流程。用户可改键，或明确选择用新流程替代原工具；替换前保存启动选择，失败恢复原状态。不得静默停用原功能或认领外部脚本。

## 最小充分验收

1. **全程可视化**：从空白搭建终端、解压及分流流程；改变快捷键、输入来源、终端位置／尺寸、解压目录／名称；保存重开后参数和引用保持一致，生成的 AHK 可由实际解释器解析，无需手改。
2. **真实行为**：在已明确告知并获准的实机步骤中，用隔离目录和自建归档验收 Explorer 文件夹／背景、桌面文件夹／背景和压缩包、隐藏扩展名、非前台窗口首次点击、普通文件／无效目标及拖拽。确认终端实际目录与位置，不移动旧窗口；确认支持格式的解压结果、连续点击和重名输出。损坏、加密或不支持的归档给出准确失败，原文件及已有目录不改。
3. **可维护及性能**：旧 v1/v2 流程字节兼容重开、手改保护和关键失败恢复通过；源引用删改、预设输入重新绑定及冲突切换失败有定向验证。对比同机原脚本的闲置 CPU、点击分发及终端就绪／解压耗时，确认没有常驻高频轮询或每次正常解压都冷启动 EXE。执行日志与结果能定位到节点。

不安排无关全量回归；涉及新协议、解压提交和版本兼容的定向检查具有必要性。实机操作前继续说明应用、步骤、测试数据和影响范围，不把规划批准视为已执行的验证。
